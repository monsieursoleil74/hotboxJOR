Manuel hotboxJOR

Le mode d’emploi de l’éditeur de hotbox et de ses librairies de boutons — fork de hotbox_designer taillé pour l’animation. Installation : README.md · Historique : CHANGELOG.md.

snapmirrorik/fkreset＋ ta librairie…

Prise en main

Vue d’ensemble

Trois fenêtres, trois rôles :

Manager

La liste des hotboxes : créer, éditer, supprimer, importer/exporter, gérer les raccourcis. La hotbox sélectionnée s’affiche en vignette (mini-rendu de tous ses boutons) pour la reconnaître d’un coup d’œil.

Éditeur

Là où on construit une hotbox. Plusieurs éditeurs peuvent être ouverts en même temps (un par hotbox).

Reader

La hotbox en production : ce qui s’affiche sous le curseur dans Maya. Non themé — son apparence, c’est ta hotbox.

Les hotboxes vivent dans hotboxes.json dans les préférences Maya (Documents\maya\<version>\prefs\) — compatibles avec l’original hotbox_designer, jamais altérées par une simple ouverture.

Prise en main

Les fichiers sur le disque

Tout ce que l’outil écrit vit à deux endroits : tes prefs Maya (personnel) et le dossier studio sur le réseau (partagé). Voilà qui fait quoi :

Côté artiste — Documents\maya\<version>\prefs\

prefs\
├─ hotboxes.jsonTOUTES tes hotboxes — l’emplacement de l’original (compatibilité)
└─ hotbox\le dossier du fork, créé au premier lancement
   ├─ button_library.jsonta librairie perso — boutons, sets, catégories, leur ordre
   ├─ hotbox_hotkey.jsonle registre des raccourcis — alimente le gestionnaire ⌨ et les listes
   ├─ studio_settings.jsonla librairie studio mémorisée — courante + liste des récentes
   └─ templates\tes templates (« Save hotbox as template » du manager)
      └─ MaHotbox.jsonun template = une copie figée d’une hotbox

Côté studio — dossier réseau (ex. R:\pipeline\hotbox\)

hotbox\pointé par le badge vert de la shelf ou HOTBOX_STUDIO_LIBRARY
├─ TAT.jsonla librairie partagée — catégories et boutons officiels (un .json par projet possible)
└─ studio_logo.pngl’icône des onglets studio (ou logo.png ; sinon logo par défaut)

Qui écrit quoi

FichierÉcrit quand…
hotboxes.jsonon sauvegarde dans le manager/éditeur (jamais altéré par une simple ouverture)
button_library.json (perso)💾 vers la perso, rename/delete/rangement dans la shelf — mode animateur
TAT.json (studio)💾 destination Studio, « Send to studio library », catégories… — mode admin uniquement
hotbox_hotkey.jsonSet/Clear dans le gestionnaire de raccourcis
studio_settings.jsonon switche de librairie via le badge / les boutons new & open
templates\*.json« Save hotbox as template » dans le manager
Trois garanties

1) Hors mode admin, l’outil n’écrit jamais dans le dossier studio. 2) Toutes les écritures sont atomiques (fichier temporaire puis remplacement d’un coup — pas de corruption possible). 3) Migration automatique : l’ancien dossier prefs\hotboxJOR\ est renommé en hotbox\ au premier lancement, et un fichier resté à la racine des prefs (vieilles versions) y est déplacé — rien à faire à la main.

En standalone (hors Maya), le dossier du fork est ~/.hotbox — même contenu, même logique.

Prise en main

Deux modes de lancement — animateur / admin

Le rôle se choisit au lancement du manager — chacun a son bouton de shelf Maya :

# animateur : la librairie studio est une RÉFÉRENCE en lecture seule
import hotbox_designer
hotbox_designer.launch_manager('maya')

# lead : mode ADMIN — la librairie officielle est éditable
import hotbox_designer
hotbox_designer.launch_manager('maya', studio_admin=True)
  • Mode animateur (par défaut) : on pioche les boutons officiels par glisser-déposer et on gère librement sa librairie perso (catégories, rename, delete). Les onglets studio sont intouchables — pas de création de catégorie, pas d’envoi vers le studio.
  • Mode admin : la shelf n’affiche que les onglets de la librairie studio courante, et tout y est éditable. Un badge Studio admin s’affiche dans le bandeau du manager et à droite de la barre d’outils de l’éditeur — on sait toujours qu’on édite l’officiel. La fenêtre, elle, s’appelle toujours « Hotbox Designer », quel que soit le mode.
  • Changer de mode sans redémarrer Maya : relancer l’autre commande dans le Script Editor — manager, badge et shelves déjà ouvertes basculent immédiatement.
Bon à savoir

C’est un garde-fou d’interface : le fichier de librairie reste accessible sur le réseau. Pour un verrouillage dur, mettre aussi le dossier studio en lecture seule au niveau des droits Windows pour les animateurs.

Éditeur

Navigation (viewport)

  1. La barre d’outils — copier/coller, undo, taille de la zone, ajout de boutons, librairie, alignements (détail).
  2. Le plan de travail — la hotbox posée sur un fond sombre infini : on y pose, déplace et redimensionne les boutons.
  3. Le panneau d’attributs — tout ce qui règle le bouton sélectionné, avec l’aperçu de ses trois états en haut (détail).
  4. La shelf de librairie — les boutons prêts à glisser-déposer, un onglet par catégorie (détail).

La zone de la hotbox est un plan de travail posé sur un fond sombre infini, façon dwpicker / Figma.

Dès qu’on navigue, la vue nous appartient et n’est plus touchée. Les poignées du manipulateur et les traits d’interface gardent une taille constante à l’écran quel que soit le zoom.

Le curseur annonce le geste : flèches de redimensionnement (↔ ↕ ⤡ ⤢) sur les bords et coins, croix de déplacement à l’intérieur de la sélection, main quand Espace est enfoncé.

Snap (désactivé par défaut)

Aucun snap n’est actif par défaut. La grille s’active par le bouton aimant rouge de la barre d’outils (+ pas x/y), comme dans l’original.

Alignement / distribution

Boutons en fin de barre d’outils (à partir de 2 shapes sélectionnées, 3 pour la distribution) :

  • Aligner : gauche, centres horizontaux, droite, haut, centres verticaux, bas.
  • Distribuer : horizontalement / verticalement — les centres se répartissent régulièrement entre la première et la dernière shape.

Zone de travail (« Fit zone »)

La zone = la taille de la fenêtre du reader dans Maya. Plutôt que de piloter les champs size à la main : pose tes boutons librement, puis clique le bouton cadre (à côté des champs size) — la zone se recadre sur la bounding box des boutons (marge 10), les shapes et le centre sont recalés (la hotbox apparaîtra au même endroit relatif sous le curseur), la vue est recadrée. Annulable.

Menu clic droit

Réduit à l’essentiel — la librairie : Save selection to library… et Replace with library button. (La recherche reste sur CtrlH, le recadrage sur F ; lock et magnet ont été retirés.)

Replace with library button : sélectionne UN bouton dans la shelf du bas, puis clic droit sur un ou plusieurs boutons du canvas → Replace. Le contenu (couleurs, texte, image, commandes…) vient de la librairie, la position et la taille sont conservées — idéal pour habiller un template sans replacer chaque bouton à la main. (Un set ne peut pas servir ici : il faut un bouton simple.)

Éditeur

Panneau d’attributs

Le panneau de droite, refondu façon Photoshop :

  • Aperçu d’états en haut du panneau : le bouton sélectionné rendu dans ses trois états (Normal / Hover / Click), mis à jour en direct à chaque réglage — couleur, bordure, texte, image, forme — sans avoir à survoler le vrai bouton dans le viewport. Section repliable comme les autres.
  • Couleurs = pastilles cliquables, les trois états sur une seule ligne ; le code hexa est dans l’infobulle. Un clic ouvre le sélecteur de couleurs maison (façon Miro) : carré saturation/valeur, teinte, hexa, couleurs prédéfinies, et la pipette ⌖ pour prélever une couleur n’importe où à l’écran (clic = prélever, Échap = annuler). Si la sélection a des couleurs différentes, la pastille affiche « … ».
  • Opacité = curseur 0–100 % (une pour le fond, une pour la bordure) — convertie vers la « transparence 0–255 » historique du JSON, rien ne change dans le format.
  • Cases à cocher pour bordure visible / gras / italique (état intermédiaire si la sélection est mixte).
  • Épaisseur de bordure = un curseur (en px) : il pilote les trois états d’un coup — survol ×1.25 et clic ×2 par rapport à la valeur normale.
  • La section Dimensions a été retirée (tout se manipule au viewport) — son champ « top » écrivait d’ailleurs dans shape.right (bug de l’original).
  • Sous-menu fluide — en haut de la section Action, le menu « Open sub-hotbox » liste les hotboxes marquées « is submenu » (dans le manager). En choisir une génère toute seule la commande d’ouverture (show('nom')) sur le clic gauche : plus besoin d’écrire une ligne de Python à la main pour enchaîner deux hotboxes. La liste reste cachée tant qu’aucune hotbox n’est marquée sous-menu.

Formes des boutons

Trois formes : square (rectangle), rounded (rectangle à coins arrondis, façon dwpicker — le rayon se règle dans le champ « Corner ») et round (ellipse). Le sélecteur est en haut du panneau d’attributs.

Éditeur

Images des boutons

Placer une image dans un bouton

Quand un bouton a une image et que « Fit to shape » est sur False, la section Image affiche deux boutons :

  • ◈ Place Image : active le mode placement (le bouton passe en vert tant qu’il est actif). On glisse l’image dans le bouton pour la positionner, la molette la redimensionne, et les Flèches la décalent d’1 unité (Maj = 10) pour un réglage au pixel près. Échap (ou re-cliquer le bouton) termine. Un contour vert en pointillés montre la position de l’image.
  • Center : recentre l’image dans le bouton.

Tout est annulable (CtrlZ). Le placement n’est possible que sur un seul bouton à la fois.

Chemins portables

Les chemins d’images sont stockés en absolu dans le JSON ; déplacer son dossier d’icônes cassait tous les logos. Désormais, si le chemin ne mène plus nulle part, l’image est retrouvée par son nom de fichier dans :

  1. le dossier pointé par la variable d’environnement HOTBOX_DESIGNER_ICONS (recommandé) ;
  2. le dossier de préférences et son sous-dossier icons/ ;
  3. les dossiers des hotboxes partagées.

Le JSON n’est jamais réécrit — seule la résolution d’affichage change.

Librairies

Librairie de boutons 📚

L’idée : configurer un bouton une fois (commande, couleurs, texte…), le ranger, le réutiliser dans toutes ses hotboxes. La librairie est une shelf en bas de l’éditeur, façon shelf Maya : un onglet par catégorie, chaque bouton affiché avec son vrai rendu en vignette. Le bouton librairie de la barre d’outils masque/affiche la shelf.

Sauvegarder un bouton

Sélectionne un ou plusieurs boutons → bouton 💾 de la barre d’outils (ou clic droit → « Save selection to library… ») → nom + catégorie. La destination est fixée par le mode : en admin, le bouton part dans la librairie studio courante (la ligne « Library » rappelle laquelle, avec le logo) ; en animateur, dans sa librairie perso. La catégorie proposée est celle de l’onglet courant de la shelf — on se met sur l’onglet voulu, 💾, OK : rapide. Le champ Category reste un menu déroulant éditable — taper un nouveau nom crée la catégorie. Toutes les shelves ouvertes se rafraîchissent.

Réutiliser

Glisse-dépose depuis la shelf vers le canvas juste au-dessus : le bouton atterrit sous le curseur, sélectionné. Multi-sélection possible. Ça marche aussi vers un AUTRE éditeur.

Organiser

  • Renommer un bouton : clic droit → Rename… (perso toujours ; studio en mode admin). Le bouton garde son apparence et sa commande, seul son nom change.
  • Supprimer : clic droit → Delete.
  • Ouvrir le dossier (JSON brut) : clic droit → « Open library folder » — ouvre l’explorateur à l’emplacement du .json (perso ou studio selon l’onglet ; sur les onglets studio, admin seulement).
  • Catégories — clic droit sur un onglet : New category… (persistée même vide), Rename category… (tous les boutons sont ré-étiquetés), Delete category (seulement si vide). Le bouton ＋ en haut à droite suit le mode : catégorie studio en admin, perso en animateur. Sur les onglets studio, ces actions demandent le mode admin.
  • Ranger dans une autre catégorie : glisser-déposer le(s) bouton(s) sur l’onglet visé (le survoler ne change pas l’affichage — on peut traverser la barre vers le canvas sans changer de catégorie) ou dans la liste à la position voulue ; ou clic droit → Move to category… Le drag reste dans la même librairie (perso↔perso, studio↔studio).
  • Réordonner : l’ordre affiché est celui du fichier — fini l’alphabétique imposé. Glisser un bouton dans sa liste pour le repositionner ; glisser un onglet (admin) pour réordonner les catégories. Tout est persisté dans le .json.

Palette flottante

Double-clic sur un onglet → la catégorie s’ouvre dans une fenêtre toujours au-dessus, en grille multi-lignes (fini le scroll dans la rangée pour une catégorie de 30 boutons). Elle reste ouverte tant qu’on ne la ferme pas, suit les changements de la librairie, se ferme si la catégorie disparaît, et tout y marche comme dans la shelf : glisser vers une hotbox, réordonner, clic droit, mêmes droits admin/animateur. Plusieurs palettes peuvent rester ouvertes côte à côte.

Filtre de recherche

Le champ « Search... » en haut à gauche de la shelf — taper un bout de nom (« snap ») remplace les onglets par un onglet unique de résultats, toutes catégories confondues (perso ET studio). Les résultats se glissent vers la hotbox comme d’habitude ; effacer le champ restaure les onglets.

Où c’est stocké

  • Perso (modifiable) : button_library.json dans le dossier du fork — Documents\maya\<version>\prefs\hotbox\ sous Maya (~/.hotbox en standalone). Le registre des raccourcis et les templates utilisateur y vivent aussi ; un fichier resté à la racine des prefs (anciennes versions) est déplacé automatiquement. hotboxes.json, lui, reste à la racine des prefs — l’emplacement de l’original (compatibilité et retour arrière).
  • Studio (partagée) : un fichier commun choisi via l’UI ou désigné par la variable HOTBOX_STUDIO_LIBRARY — voir Librairie studio.
Écritures protégées

Chaque écriture d’un fichier de données (librairies, hotboxes.json, raccourcis, réglages) est atomique : le contenu part dans un fichier temporaire puis remplace l’original d’un seul coup — un crash en pleine écriture ne peut pas corrompre le fichier. Aucun fichier annexe n’est créé : les sauvegardes historiques restent à la charge de l’utilisateur (copie manuelle) ou du studio (backups quotidiens).

Librairies

Sets de boutons

Avec plusieurs boutons sélectionnés, le dialogue de sauvegarde 💾 propose une case « Save the N buttons as one set (keeps layout) ».

  • Cochée : la sélection devient UN SEUL élément de librairie qui garde la disposition relative des boutons — un kit main IK, une rangée de snaps…
  • Décochée (défaut) : comportement historique, N boutons indépendants « nom, nom 2, nom 3… ».

Dans la shelf, le set se reconnaît à sa vignette groupée (l’infobulle précise le nombre de boutons). Au dépôt dans une hotbox, les N boutons sont recréés d’un coup, disposés comme à l’origine et centrés sous le curseur.

Un set se renomme, se range, se réordonne et se supprime comme un bouton simple — et se publie vers la librairie studio pareil. Seule exception : « Replace with library button » demande un bouton simple, pas un set.

Librairies

Librairie studio

Une librairie partagée (les catégories officielles du studio), affichée en tête de la shelf avec le logo du studio en icône d’onglet. En mode animateur elle est une référence en lecture seule ; en mode admin elle est éditable.

Choisir / changer de librairie (par projet)

Dans le coin de la shelf, pour tout le monde (la librairie reste en lecture seule hors mode admin) :

  • Le badge vert ringo affiche le nom du fichier de la librairie courante et c’est lui le sélecteur : cliquer dessus ouvre la liste des librairies (récentes + courante cochée) pour switcher de projet. Une librairie dont le fichier a disparu est marquée « (missing) » et non cliquable ; le sous-menu Remove from list retire une librairie obsolète de la liste (le fichier n’est pas touché).
  • Le bouton page (new) — admin uniquement — crée une librairie : dialogue « Enregistrer sous », nom du .json libre (ringo.json, projetX.json…). À la création, le logo courant est copié à côté du nouveau fichier — la nouvelle librairie garde l’identité du studio. Choisir un fichier existant l’ouvre, jamais d’écrasement.
  • Le bouton dossier — pour tout le monde — ouvre/charge une librairie existante.

Aucune librairie par défaut : au tout premier lancement il n’y en a pas (pas de badge, pas d’onglets studio) — on en crée/ouvre une explicitement, et seules celles réellement chargées vivent dans la liste. Le choix est mémorisé entre les sessions (studio_settings.json dans prefs/hotbox/) et prend le pas sur la variable d’environnement.

Rafraîchissement automatique

La librairie courante est surveillée : quand le lead publie un bouton, les shelves ouvertes des animateurs se rafraîchissent toutes seules.

Publier vers la librairie studio (mode admin)

Clic droit sur un ou plusieurs boutons de la shelf → « Send to studio library », ou directement 💾 avec la destination Studio. Les boutons sont copiés dans la librairie studio (dédupliqués) et les onglets se rafraîchissent — pas de fichier à copier à la main. En mode animateur, ces actions n’existent pas. Alternative manuelle : copier son button_library.json dans le dossier studio.

Mettre en place la librairie (workflow lead)

  1. Lancer le manager en mode admin (launch_manager('maya', studio_admin=True)).
  2. Créer les catégories officielles (clic droit sur un onglet studio → New studio category…) et y ranger les boutons (💾 destination Studio, ou Send to studio library depuis la perso).
  3. Chaque animateur voit automatiquement les onglets studio (logo) + ses onglets perso. Pour pointer le chemin au déploiement : définir HOTBOX_STUDIO_LIBRARY (variable d’environnement Windows, ou dans le userSetup.py commun : os.environ['HOTBOX_STUDIO_LIBRARY'] = r"P:\pipeline\hotbox" — un .json direct, ou un dossier contenant button_library.json).

Logo du studio

Pose un studio_logo.png (ou logo.png) dans le dossier de la librairie studio — il devient l’icône des onglets. On peut aussi pointer un fichier précis via la variable HOTBOX_STUDIO_LOGO. Sans rien, un logo par défaut est utilisé. Un logo différent par projet est possible.

Templates

À la création d’une hotbox, les templates s’affichent en grille de vignettes cliquables : tous visibles d’un coup (embarqués puis persos), clic = sélectionner, double-clic = créer directement — la vignette EST l’aperçu. « Duplicate existing » garde son menu, avec un aperçu qui n’apparaît que quand cette option est cochée.

Les templates embarqués sont ceux hérités de l’original, plus le template TAT (la hotbox de base du studio : grille de boutons prête à câbler). Combinés à « Replace with library button », ils permettent de monter une hotbox rapidement : créer depuis le template, puis remplacer chaque bouton par un bouton de la shelf.

Créer ses propres templates : sélectionne une hotbox dans le manager → bouton Save hotbox as template (💾 de la barre d’outils du manager, à côté d’export). Elle est copiée dans templates/ du dossier de données et apparaît dès lors dans la liste « From template », après les templates embarqués. Un template est une copie figée : modifier la hotbox d’origine ne le change pas.

Raccourcis clavier (gestionnaire)

Le raccourci assigné à chaque hotbox s’affiche directement dans les listes du manager (en grisé, à droite du nom, onglets Personal et Shared) — plus besoin d’ouvrir le gestionnaire juste pour vérifier.

Le bouton ⌨ de la barre d’outils du manager ouvre le gestionnaire de raccourcis : un tableau qui liste toutes les hotboxes avec la touche qui leur est assignée.

  • Voir — chaque ligne montre la hotbox et sa touche (ou « — » si aucune).
  • Set… / Change… — ouvre le sélecteur de touche : on tape directement la combinaison (ex. MajQ) dans le champ Shortcut et elle s’affiche telle quelle. Plus besoin de cocher Ctrl/Alt/Shift : les modificateurs sont lus sur la frappe. Échap efface. On choisit ensuite le type d’événement.
  • Clear — retire le raccourci. Sous Maya, la touche est réellement débranchée (press ET release), pas seulement oubliée.

Sous le capot, un petit fichier hotbox_hotkey.json (dossier de données du DCC) tient le registre des raccourcis, commun à tous les backends — c’est lui qui alimente le tableau. Les raccourcis globaux n’existent que dans un DCC (Maya, Nuke…) : hors DCC le tableau l’indique et les boutons Set sont désactivés. Si le set de hotkeys Maya courant est verrouillé (Maya_Default), l’éditeur de hotkeys de Maya s’ouvre pour le changer.

Sous le capot

Pour s’y retrouver dans le code :

  • Coordonnées : les shapes vivent dans l’espace de la hotbox (« unités ») — le JSON est identique à l’original. Le viewport applique zoom + translation au rendu (ViewportMapper dans geometry.py, adapté de dwpicker) ; les événements souris sont convertis en unités avant toute logique.
  • Undo : modèle « snapshot » — chaque modification pousse une copie profonde de la hotbox complète (UndoManager, designer/application.py).
  • Presse-papier : boutons et styles transitent par le presse-papier système en JSON avec une clé marqueur — d’où le fonctionnement inter-fenêtres et inter-sessions.
  • Multi-éditeurs : le manager lie chaque fenêtre d’édition à sa hotbox par identité d’objet (_EditorLink), pas par ligne sélectionnée.
